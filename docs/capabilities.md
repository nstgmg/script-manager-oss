# Script Manager로 할 수 있는 일

Script Manager는 **반복 작업을 스크립트로 만들어 운영하는 로컬 도구**입니다. 사용자는 에이전트에게 원하는 일을 설명하고, 에이전트는 스크립트를 작성하거나 실제 관리 상태를 조회합니다. Script Manager 자체에 자연어 대화 엔진이나 업무별 수집기가 들어 있지는 않습니다. 시작은 [README](../README.md), 요청 방법은 [사용자 가이드](../USER_GUIDE.md), 설치는 [INSTALL](../INSTALL.md)을 따르세요.

## 목적에 따라 고르기

아래 업무 예시는 작성 가능한 자동화의 예이며, 설치 직후 사용할 수 있는 완성 Job 목록이 아닙니다.

| 하고 싶은 일 | 에이전트에게 할 요청 | 기본 제공 기능 | 별도 스크립트·준비가 필요한 부분 |
| --- | --- | --- | --- |
| 지원사업·채용·정책 공고 모으기 | “지정한 사이트의 공고를 모아 제목·마감일·URL을 저장하고 싶어.” | Job 등록·실행·예약, 결과 저장 경로와 조회 | 사이트/API별 수집, 이용 조건·접근 권한 확인, 날짜·상태 정규화와 중복 처리 |
| CSV·JSON 등 반복 파일 정리 | “이 폴더의 CSV를 같은 형식으로 정리하는 작업을 만들어 줘.” | 스크립트 실행, 실행별 Output·로그·시간 제한 | 입력 위치·형식·변환 규칙에 맞는 코드, 필요한 라이브러리 준비 |
| 여러 작업 결과 비교 | “두 수집 작업의 저장 결과를 비교해서 차이를 보고 싶어.” | 다른 Job의 기록 Output을 읽을 표준 경로 제공 | 비교 기준과 집계 스크립트, 결과 스키마 설계 |
| 작업 상태와 실패 확인 | “만든 작업과 최근 실행 결과를 보여줘.” | Job 정의·Run 이력·상태·stdout/stderr 조회 | 업무상 성공 기준은 각 Job 계약에 맞게 확인; 수정이 필요하면 에이전트가 코드 변경 |
| 저장된 공고·레코드 찾기 | “저장된 결과에서 용인 관련 모집 중 공고를 보여줘.” | 날짜·키워드·상태·출처·페이지별 저장 결과 조회 | 해당 결과 파일과 필드가 있어야 함; 키워드가 지원 자격이나 현재 상태를 보증하지 않음 |
| 결과를 브라우저에서 보기 | “저장된 JSON을 HTML 보고서로 만들어 줘.” | 서버 없는 HTML 변환, 검색·필터·정렬·CSV 내보내기 | 입력 JSON 준비; 업무별 차트·요약·맞춤 화면은 별도 작성 |
| 정기적으로 실행 | “확인한 작업을 매일 오전 9시에 예약해 줘.” | 한 Job에 여러 요일·시각/간격 Schedule, 지원 OS 등록·상태 조회 | 시각·실행 호스트 시간대·활성화 승인, 의존성·자격증명 및 실제 성공 검증 |
| 화면에서 관리 | “Dashboard를 시작해 줘.” | 로컬 현황, Job 설정·실행·로그, Schedule, 보고서, Package·보존·휴지통 관리 | 명시적 서비스 시작 요청과 호스트 접근; 수집·변환 코드 편집은 에이전트가 담당 |
| 내보내기·원격 운영 검토 | “이 Job의 Package와 Linux 배포 제한을 설명해 줘.” | 불변 ZIP, 선택한 Package의 오프라인 배포 계획, 제한적인 SSH 배포·검증·롤백 | 대상 환경·의존성·SSH 준비, 별도 승인; 아래 원격 제한 확인 필수 |

메일·메신저 알림, 특정 사이트 로그인, PDF/엑셀 업무 처리 같은 기능은 해당 연동·라이브러리와 스크립트를 별도로 준비해야 합니다. 알림 서비스나 자격증명, 외부 데이터는 포함하지 않습니다. 유일한 공개 예제 [hello-output](../examples/hello-output/README.md)은 네트워크 없이 합성 레코드 두 개를 만드는 설치 확인용입니다.

## 제품이 맡는 범위

Job은 **무엇을 실행할지**(명령·환경·제한시간·공개 입력)를 정의하고, Schedule은 **언제 실행할지**를 정의합니다. 실행 한 번의 기록이 Run이며 Output은 그 실행이 저장한 결과입니다. Job마다 여러 Schedule을 둘 수 있고, 에이전트가 계속 접속해 있지 않아도 준비된 스크립트를 실행할 수 있습니다. OS 예약은 실행 호스트의 로그인·전원·절전 정책 영향을 받습니다.

기본 실행에는 DB·LLM API·Node·프런트엔드 빌드가 필요 없습니다. 스크립트에 필요한 실행 파일과 라이브러리는 별도로 준비합니다. Dashboard는 설정과 운영 화면이며 코드를 작성하지 않습니다. 일반 CLI 실행·저장 결과 조회·HTML 변환에 Dashboard가 필요하지 않습니다.

다음은 기본 제공을 약속하지 않는 범위입니다.

- 업무별 수집기·완성 데이터, 자연어를 자체 처리하는 채팅 서비스
- 스크립트 의존성 자동 설치, Job 전체 자동 재시도, 절전 중 누락 작업의 재실행 보장
- 여러 호스트에 걸친 중복 실행 방지·중앙 원격 모니터링·원격 로그/결과 동기화
- 비신뢰 코드를 격리하는 sandbox, 인터넷에 공개하는 다중 사용자 Dashboard

동일 로컬 Job의 동시 실행은 잠금으로 제한하지만 업무 데이터의 중복 방지는 스크립트가 설계해야 합니다. [운영 계약](operations.md)과 [작성 지침](script-authoring.md)에 자세히 나와 있습니다.

## OS별 지원과 확인 수준

아래는 기존 검증 기록의 범위이며 이번 온보딩 문서 정비에서 새 플랫폼 검증을 수행한 것은 아닙니다.

| 기능 | macOS | Windows | Linux |
| --- | --- | --- | --- |
| CLI·수동 실행·저장 결과·HTML·Dashboard | ARM64 / Python 3.13.18 독립 설치 실검증; 과거 3.9.6 기록 보존 | 구현·모의 테스트, 실제 설치 미검증 | POSIX 구현, 실제 설치 미검증 |
| 로컬 OS 예약 | launchd 구현, 기존 독립 설치 검증에서 native 적용 안 함 | Task Scheduler 구현, 실환경 미검증 | 미지원 |
| SSH 배포 대상 | 미지원 | 미지원 | systemd user 구현, 실서버 미검증·제한 있음 |

Python·OS 준비와 상세 지원은 [INSTALL](../INSTALL.md#지원-범위와-사전-준비), 검증 근거는 [검증 기록](validation.md)·[공개 준비 기록](public-readiness.md)을 확인하세요. Intel macOS·다른 Python 버전·다른 브라우저까지 확인됐다고 확대 해석하지 않습니다.

원격 Linux에서는 `required_env`를 선언한 Job의 환경 구성이 실패하고, 로컬 표준 Output·State·Workspace 경로 주입·HTML 생성·로그/결과 동기화가 제공되지 않습니다. `verified`는 파일·systemd 적용 확인이며 업무 실행 성공이 아닙니다. 현재 로컬 Job을 그대로 올려 동일하게 운영할 수 있다고 안내하지 않습니다. [Package·원격 제한](packages.md)을 먼저 확인하세요.

## 요청과 승인

기능 질문은 안내, 저장 데이터 질문은 조회로 처리합니다. 새 수집·실행·예약·서비스 시작·배포는 사용자가 요청한 범위 안에서 진행합니다. “최신 결과”라는 말만으로 재수집하지 않습니다. 활성 예약 변경·삭제·정리·실제 SSH 작업에는 기존 승인이 필요합니다. 설치 요청에 포함되는 합성 예제 검증 범위와 실제 업무 실행은 [INSTALL](../INSTALL.md#에이전트가-진행할-범위)에서 구분합니다.

Job은 사용자 OS 권한으로 실행됩니다. 비밀값은 사용자가 루트 `.env`에 직접 등록하며 에이전트는 실제 값을 읽지 않습니다. [사용자 가이드](../USER_GUIDE.md)에서 필요한 입력과 다음 요청을 고르고, [보안 정책](../SECURITY.md)을 따르세요.
