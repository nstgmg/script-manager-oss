# Script Manager v0.1.0

### 에이전트로 자동화 작업을 만들고, 반복 실행은 AI 호출 없이 처리합니다.

AI 에이전트를 이용하면 프로그래밍을 몰라도 반복 업무를 자동화할 수 있습니다. 원하는 작업을 자연어로 설명하면 에이전트가 코드를 작성하고 실행까지 도와줍니다.

하지만 일부 에이전트 기반 자동화는 같은 작업을 반복할 때도 실행 방법을 판단하고, 명령을 생성하고, 결과를 확인하는 과정에서 여러 번 모델을 호출합니다. 이 과정에는 비용과 대기 시간이 발생합니다.

이미 처리 방법이 정해진 작업이라면 매번 AI가 다시 판단할 필요는 없습니다. **한 번 작성한 스크립트를 그대로 실행하면 됩니다.**

Script Manager는 이러한 자동화 작업을 내 컴퓨터에서 실행하고 관리하기 위한 무료 오픈소스 도구입니다.

사용자는 코드를 몰라도 에이전트에게 자연어로 요청해 작업을 만들고 운영할 수 있습니다. **에이전트의 편리한 사용 경험은 유지하면서, 반복 실행에 필요한 AI 비용과 대기 시간을 줄이는 것이 목표입니다.**

## 어떻게 사용하나요?

Script Manager를 처음 한 번 설치하면 여러 자동화 작업을 추가하고 관리할 수 있습니다.

지원사업 공고 수집을 예로 들어보겠습니다.

### 1. 자동화 작업 만들기

> 기업마당과 K-Startup에서 모집 중인 지원사업 공고를 수집하는 작업을 만들어 줘.

에이전트가 필요한 조건을 확인하고 스크립트를 작성해 Script Manager에 등록합니다. 한 번 실행해 결과를 확인하고, 필요한 부분을 수정할 수도 있습니다.

### 2. 원하는 방식으로 실행하기

등록한 작업은 다음 네 가지 방법으로 실행할 수 있습니다.

- **에이전트:** “지원사업 공고 수집 작업을 실행해 줘.”라고 자연어로 요청합니다.
- **예약 실행:** “매일 오전 9시에 실행해 줘.”라고 설정합니다. 이후에는 에이전트 개입 없이 OS가 정해진 일정에 따라 실행합니다.
- **CLI:** 터미널에서 명령어로 실행합니다.
- **Dashboard:** 로컬 관리 화면에서 작업을 선택해 실행합니다.

어떤 방식이든 이미 등록된 스크립트를 실행합니다. 사용자가 코드를 직접 다루거나 실행 파일을 찾아 더블클릭할 필요는 없습니다.

예약 실행은 컴퓨터가 켜져 있고 OS에서 작업을 실행할 수 있는 상태여야 합니다.

자연어로 실행을 요청하면 에이전트 사용에 따른 모델 호출이 발생하지만, CLI·Dashboard·OS 예약을 통한 스크립트 실행 자체에는 AI 추론이 필요하지 않습니다.

### 3. 결과를 활용해 새로운 산출물 만들기

스크립트가 수집하거나 처리한 결과물은 파일로 저장됩니다.

사용자는 에이전트에게 자연어로 요청해 이 결과물을 자유롭게 활용할 수 있습니다.

> 오늘 수집한 공고 중 마감이 가까운 것들을 보여줘.

> 우리 사업에 적합한 공고를 추려서 비교표와 HTML 보고서로 만들어 줘.

에이전트는 저장된 결과물을 읽고 분석하거나 가공해 새로운 산출물을 만듭니다. 이미 확보한 자료를 활용하므로 수집 작업을 다시 실행할 필요도 없습니다.

### 4. Dashboard에서 관리하기

> Dashboard를 열어 줘.

내 컴퓨터에서 실행되는 Dashboard를 통해 작업 목록, 실행 상태, 예약 일정, 로그와 저장된 결과를 직접 확인하고 관리할 수 있습니다.

별도의 온라인 서비스가 아니라 로컬에서 실행되는 관리 화면입니다.

브라우저 제어를 지원하는 에이전트와 같은 화면을 보면서 작업할 수도 있습니다.

## 어떤 일을 자동화할 수 있나요?

**파일 정리와 변환**

여러 CSV나 JSON 파일을 합치고, 필요한 항목만 추려 정해진 형식으로 저장할 수 있습니다.

**정기적인 자료 수집**

여러 사이트나 API에서 정보를 수집하고, 날짜별로 저장하거나 이전 결과와 비교할 수 있습니다.

**결과물 분석과 보고서 생성**

스크립트로 확보한 데이터를 에이전트와 함께 활용해 요약, 비교표, 보고서, 글의 초안 등 새로운 산출물을 만들 수 있습니다.

개별 업무를 처리하는 스크립트는 사용자가 원하는 조건에 맞춰 에이전트가 작성합니다. Script Manager에 모든 업무용 자동화가 미리 포함된 것은 아닙니다.

## 왜 이렇게 만들었나요?

Script Manager는 **에이전트를 통한 작업 생성과 관리의 편리함은 유지하면서, 실제 스크립트 실행을 에이전트의 추론 과정에서 분리**하기 위해 만들었습니다.

반복적으로 실행할 작업은 코드로 만들어 OS에서 처리하고, 새로운 작업을 설계하거나 결과를 해석하고 가공하는 데는 에이전트를 활용합니다.

이러한 구조에는 세 가지 목적이 있습니다.

- **비용 절감:** 이미 정해진 작업을 반복하면서 발생하는 불필요한 모델 호출을 줄입니다.
- **실행 지연 감소:** 작업을 실행할 때마다 에이전트가 여러 단계의 판단을 수행할 필요가 없습니다.
- **사용 편의성 유지:** 사용자는 코드를 몰라도 자연어로 자동화를 만들고 관리하며, 저장된 결과물로 새로운 작업을 이어갈 수 있습니다.

Script Manager는 에이전트를 대체하지 않습니다. **에이전트가 잘하는 일과 일반 프로그램으로 충분한 일을 구분해 함께 활용하는 방식**입니다.

개발에 익숙하지 않은 사람도 복잡한 실행 명령어나 예약 설정을 직접 다루지 않고 자동화를 운영할 수 있습니다. 개발자는 여러 스크립트의 실행과 결과를 한곳에서 관리할 수 있습니다.

## 처음 설치하기

Script Manager는 처음 한 번만 설치하면 됩니다. 새로운 자동화 작업을 추가할 때마다 다시 설치할 필요는 없습니다.

Codex나 Claude Code 같은 코딩 에이전트에서 프로젝트 폴더를 만들고 다음과 같이 요청하면 됩니다.

> [https://github.com/nstgmg/script-manager-oss](https://github.com/nstgmg/script-manager-oss)
>
> 이 프로젝트를 설치해 줘.

에이전트가 GitHub 저장소에 포함된 설치 지침을 읽고 필요한 환경을 준비하도록 구성했습니다.

설치 후에는 같은 프로젝트에서 새로운 작업을 계속 추가할 수 있습니다.

사용법이 궁금하다면 에이전트에게 “이걸로 뭘 할 수 있어?”라고 물어보면 됩니다. 저장소의 문서와 구현 내용을 확인해 사용 방법을 안내할 수 있습니다.

## v0.1.0 지원 범위

첫 버전에는 작업 등록과 실행, OS 예약, 실행 기록 및 로그 조회, 저장 결과 검색, HTML 보고서 생성, 로컬 Dashboard 등이 포함돼 있습니다.

**macOS ARM64 환경에서는 주요 기능의 실제 동작 검증을 완료했습니다.**

Windows용 작업 실행 및 작업 스케줄러 연동 기능도 구현했지만, 실제 Windows 환경에서의 설치와 실행 검증은 완료되지 않았습니다.

Linux 관련 기능과 systemd 기반 SSH 원격 배포 기능도 구현돼 있으나 실제 서버 환경에서의 검증은 완료되지 않았으며, 일부 실행 환경과 결과 관리에 제약이 있습니다. Linux 로컬 예약은 지원하지 않습니다.

Script Manager 자체에는 AI 모델이 포함돼 있지 않습니다. 스크립트 실행 자체에는 AI 호출이 필요하지 않지만, 스크립트가 별도로 AI API를 사용하거나 에이전트로 결과를 분석하는 경우에는 해당 비용이 발생할 수 있습니다.

모든 작업은 사용자 OS 권한으로 실행되며, 신뢰할 수 있는 코드를 사용하는 로컬 단일 사용자 환경을 전제로 합니다.

소스 코드와 자세한 사용 방법은 [Script Manager GitHub 저장소](https://github.com/nstgmg/script-manager-oss)에서 확인할 수 있습니다.

직접 문서를 읽는 대신, 저장소에 접근할 수 있는 에이전트에게 GitHub 주소를 전달하고 “이 프로젝트로 무엇을 할 수 있고, 어떻게 사용하는지 알려줘”라고 요청해도 됩니다.
